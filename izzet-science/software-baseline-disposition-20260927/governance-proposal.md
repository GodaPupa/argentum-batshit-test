## A separate unresolved reference-policy boundary

It would be false to call all current LEGACY_V0 behavior unchanged. Complete immutable AI subtree comparison finds 227 original and 228 current production files: 225 existing files match, DecisionResponder and GameSimulator differ, and YesNoDecisionStrategy is added. ArenaGameRunner and TableGameRunner are byte-identical. AiProfile and AIPlayer are byte-identical, but that is insufficient: ArenaAgents maps v0 to AiProfile.LEGACY_V0; AIPlayer.create does not pass a Yes/No strategy, so the current DecisionResponder default selects COMPLETED_BRANCH_V1. The original accepted source implemented simulate-both Yes/No. The current LEGACY_SIMULATE_BOTH_V1 selector exists but is not selected by that factory.

The all-vanilla fixture does not exercise these Yes/No branches, and its complete observed action stream has only the seven described priority differences. That limited observation supports an exact-fixture software expectation disposition. It does **not** resolve the broader default-strategy drift, authorize policy tuning, validate hidden-information boundaries, or qualify a frozen experimental pilot. That issue is reported separately and remains a receiving/admission blocker wherever the changed behavior is reachable. The proposed baseline disposition must explicitly retain it, rather than use a green baseline to conceal it.
