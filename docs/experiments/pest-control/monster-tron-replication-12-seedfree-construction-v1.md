## Construction boundary

The new Python module validates canonical, digest-bound excluded fixture inputs
against twelve ordered slots and the adopted repeated four-cell seat/starter
schedule. Labels are opaque `EXCLUDED_FIXTURE_SLOT_01` through `12`, not seeds.
The source parameter verifies the exact inherited smoke baseline identity; it
is not an attestation of the current checkout. Qualification separately binds
these newly added source bytes by Git blob and SHA-256.

All future official source/tree/vector/assignments/archive/exclusions/claim/
workflow/authority bindings remain null. `load_official` always rejects, including
validation or execution ACK strings. There is no entropy acquisition, official
vector generation, engine import, engine initialization, gameplay callback,
claim API, network client, subprocess, workflow, or execution entry point.

The coordinator writes actual local fixture evidence with exclusive creation,
file flush/fsync followed by directory fsync, and checks complete exact inventory
and hashes before recording fixture completion. It requires attempt before
initialization-entry tokens and matched durable intent/result tokens before each
fixture record. Tokens simulate evidence transitions only: no game runs and no
winner is produced. Every record identifies the excluded fixture realm.

Wrong transitions or write/force uncertainty permanently poison that object.
Existing directories are never reopened, resumed, deleted, or adopted; existing
files are never overwritten. Partial prefixes remain for diagnosis. Completion
requires all twelve fixture records; an incomplete prefix cannot be summarized
as a complete experiment. A second completion or thirteenth slot is rejected.
