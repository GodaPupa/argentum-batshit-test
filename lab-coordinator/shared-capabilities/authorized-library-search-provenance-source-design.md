## Typed declaration and proof

1. Add a distinct SDK `CardSource.AuthorizedLibrarySearch` with one resolved library owner, one resolved searcher, a gather filter, and `LibrarySearchPortion.Whole` or `Top(count)`. This source is opt-in only for a rules-authorized search; ordinary `FromZone(LIBRARY)`, `TopOfLibrary`, `FromMultipleZones`, and `FromVariable` do not confer it. Reject multi-player or unresolved owner/searcher references. Add an explicit typed `SelectFromCollectionEffect` search-order request; the ordinary Select default has none. The audited `LibraryPatterns.searchLibrary` helper declares the whole-library producer and its immediately matching consumer. Do not auto-mark `searchMultipleZones`, top-N looks, or card-name patterns. Document the SDK variants in `docs/card-sdk-language-reference.md`.
2. At a successful authorized Gather, the executor uses only the declared permitted portion of that owner's current library (a top-N search restricts the gathered prefix **before** applying its search filter). It returns its normal named collection and an engine-internal, nonserialized, one-step candidate: collection name, exact gathered physical entity IDs in library-relative order and their object generations, resolved owner/searcher, portion descriptor, captured `ObjectReferenceEnvironment.origin` and `resolutionKey`. Both identity fields must be present. The original source object remains the origin after a cost moves it; a new object at the same entity ID cannot replace the captured generation. No absolute library index or unseen remainder is placed in the candidate.
3. `CompositeEffectExecutor` and `EffectContinuationRunner` retain that candidate **only for the directly following sibling Select**. They pass it solely in the execution context of that step, never in a pre-pushed continuation frame. Any other step, nested composite boundary, error, pause before the matching Select, alternate collection write, or finished/automatic selection discards it. This deliberately fails closed for more complex pipelines. It avoids a persistent search-order map on `GameState` or `PipelineState` and avoids post-search hidden-order retention.
4. The matching Select must ask the resolved searcher, have the exact producer collection name and values, request search-order authority explicitly, and offer exactly the producer's eligible physical handles in the same order. It must have no additional Select filter, `showAllCards`, nonselectable list, concatenation, copied collection, or unqualified derivation. Check distinct entity handles (duplicate names are fine), current library membership and the captured object generations, permitted owner/portion, captured source origin and resolution key. An absence or mismatch produces an ordinary canonical decision without order authority, not a gameplay failure. Existing legal action validation remains unchanged.
5. Only `SelectFromCollectionExecutor.createDecision`, after those checks, attaches a typed `AuthorizedLibrarySearchChoice` to the one `SelectCardsDecision`. The value contains the generated engine decision ID, chooser/actor seat, owner, portion descriptor, captured source object reference and resolution key, and exactly `decision.options` as ordered physical handles. It excludes the remainder, nonselectable cards, absolute indices, raw continuation, RNG and future library order. The pending decision's suspension is the sole lifetime: answer, cancellation, replacement or restoration to another pending ID removes it. The engine ID is a routing identity, not the browser/actor epoch.
6. The Pest receiver is a separate coherent source integration. Its `ActorEpoch(sourceVersion,trialId,step)`, binding hash and expected actor/decision ID must be checked when `ObservationAdapter` builds input. Preserve option order only when the currently pending typed proof matches all those bindings; otherwise retain `ActorDecisionProjection`'s canonical EntityId sort. Always canonicalize `nonSelectableOptions` and ordinary looks/actions. A stale/forged proof cannot authorize a later observation. Main `ff34ac8f` does not contain that actor-input layer; do not merge the distant Pest branch merely to compile the generic engine.

## Exact source and continuation seams

- Producer/consumer: `mtg-sdk/.../effects/PipelineEffects.kt`, `mtg-sdk/.../dsl/LibraryPatterns.kt`; `rules-engine/.../effects/library/GatherCardsExecutor.kt`, `SelectFromCollectionExecutor.kt`; `handlers/EffectContext.kt`; `core/EffectResult.kt`; `core/PendingDecision.kt`.
- Synchronous siblings: `effects/composite/CompositeEffectExecutor.kt` and `continuations/EffectContinuationRunner.kt`. The candidate is not part of `updatedCollections` or a generic pipeline collection. Existing `storedCollections - initial.keys` drops overwritten existing keys; never use that difference to propagate authority. Every intervening effect, including an overwrite with identical contents, revokes the local candidate.
- Pause and resume: `GameState.suspendForDecision` allocates the exact ID and stores the decision in the `Suspension`; `SelectFromCollectionContinuation` captures normal card collections, and `LibraryAndZoneContinuationResumer.resumeSelectFromCollection` publishes selected/remainder. No candidate enters either continuation or `PipelineState`; the proof lives on the unanswered decision only. `PipelineCollectionPropagation.exposeCollectionsToNextFrame` handles `EffectContinuation`, `ReflexiveTriggerTargetContinuation`, `GatedActionContinuation`, ForEach accumulation and RepeatWhile body collections; all remain order-unprivileged. `CoreAutoResumerModule` and `EffectAndTriggerContinuationResumer` republish generic collections after drains/gates, also without a candidate. This is a deliberate fail-closed boundary for copied, concatenated, filtered or overwritten collections.
- Actor/public projection: `GameSession.createStateUpdate` sends the pending decision only to `state.actorFor(decision.playerId)`; the other player receives only `DecisionEnricher.createOpponentDecisionStatus`. `PendingDecisionRouting.withClientRoutingId` prefixes the live `GameSession.liveInteractionEpoch`, which changes on undo/recovery; `useEngineDecisionIds` keeps in-process AI replay IDs. The typed field would serialize in a paused engine snapshot and chooser-facing decision, so verify those exact paths plus spectator state, websocket payload and client schema before acceptance. No general `ClientGameState`, zone view, event or opponent status receives it. The Pest actor sanitizer must explicitly whitelist only this binding; SDK schema alone is insufficient.
