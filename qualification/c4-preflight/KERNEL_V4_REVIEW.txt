IMPLEMENTED PATH
supervise_probe() is a callable OS backend for a future separately authorized
active containment validation. It is not a command-line program. Its only exec
image is /usr/bin/true, opened by FD and recorded by SHA256/inode. There is no
caller-selected executable, compiler argv, environment permit, or JSON approval.
compile_request() always refuses. preflight.py remains BLOCKED. Deleting that
return does not reveal compiler orchestration; it was removed in V3.

The backend requires actual UID/EUID 0; rejects an in-use worker UID, unsafe
root-owned paths, symlinks, ambiguous cgroup2 mounts, non-root mount mappings,
global root as parent, missing/unenabled memory delegation, writable migration
ancestors, existing evidence paths, and missing cgroup.kill. It does not enable
controllers or alter parent permissions. It creates an exclusive group itself,
retains directory/counter FDs and boot/inode identities, and requires fresh zero
creation counters before fork. Creation positives are retained as FAIL.

The direct fork child waits on a CLOEXEC pipe. Parent joins it to cgroup.procs
before releasing setup. Trusted setup unshares network/IPC/mount namespaces,
makes mount propagation private, mounts private tmpfs at /tmp and /dev/shm,
brings up only private loopback, clears environment and inherited descriptors,
drops supplementary groups, all UID/GID identities and all capability sets,
sets NoNewPrivs, and installs libseccomp. The parent verifies kernel /proc
credentials/capabilities, Seccomp, NoNewPrivs, PID/start, membership, population
and differing namespace identities while the child is still held pre-exec.
Only then does it release the fixed image. Unknown capabilities fail closed.

Filter denies namespace-changing calls and clone namespace bits, clone3 returns
ENOSYS, and ordinary fork/thread clone remains possible. It denies mount/pivot,
ptrace/process_vm_writev, pidfd_getfd, BPF, keyring and io_uring entry paths.
AF_UNIX socket/socketpair are denied because pathname UNIX sockets can cross a
network namespace. Network namespace has private loopback and no external link;
external same-JDK and different-JDK daemons are unreachable by its IP stack.
The worker's cgroup/ancestor interfaces remain root-owned and non-writable;
capability/namespace recovery is blocked. This is proposed kernel enforcement
source, not enforcement evidence from the runner. UID-exclusivity discovery is
conservative and fails on racing/unreadable inventory. Root administrators and
kernel are in the trusted computing base; a hostile privileged host is outside
this claim. The supervisor source/launcher must itself be protected and pinned.

Lifecycle uses pidfd for the known launcher and cgroup.kill for all descendants,
including reparented/double-forked workers. It waits boundedly for populated=0,
then reads the SAME held memory.events FD, saves evidence before removal, and
retains cleanup failures. Missing counters, reset, identity changes or missing
final drain cannot produce clean evidence. Positive intervals survive gaps.
Parent stays outside the target. If pidfd_open fails before release, cleanup
uses only its direct unreaped child (not an untrusted scanned PID).

Before release the supervisor retains private /tmp and home directory FDs.
Post-drain log capture follows those handles, not host /tmp. It rejects symlinks,
aliased/nonregular files, replacement/size races and oversized collections;
records raw copied bytes, hashes, inode, run and scope. Shared jvm_evidence.py
retains V3 fatal/ambiguous/empty/missing-log rules, including required compiler,
Gradle and Kotlin roles. A private-directory origin does not establish that any
arbitrary worker log line is true or prove an individual JVM writer. The fixed
true probe has NO compiler/JVM logs; missing roles cannot qualify C4.
