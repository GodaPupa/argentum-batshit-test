THREAT MODEL AND PROPOSED TRUST BOUNDARY
The future trusted computing base would be an independently reviewed privileged
outer supervisor, kernel, pinned executable/toolchain/source, authenticated
owner launch identity and protected immutable evidence channel. Worker code,
workspace files, process-name strings, worker JSON/log messages, environment,
external daemons and repeated run IDs are not trusted containment authorities.
A compromised host/kernel or privileged outside actor remains outside any local
worker-isolation claim; an administrative writer could invalidate the evidence.
Neither synthetic booleans nor a hash chain proves that this trust boundary exists.

The containment_model.py state machine is ONLY an executable specification for
fixtures. It performs no OS isolation or process operations. Even a SEALED model
returns BLOCKED_D2/qualifying=false. Model states:
NEW -> CREATED -> RUNNING -> DRAINING -> SEALED; any missing prerequisite REFUSED.
Positive model OOM evidence is retained as model FAIL even with later gaps.

PROPOSED SUPERVISOR LIFECYCLE (UNIMPLEMENTED)
1. Validate authenticated run/source/manifest binding and unique output path.
   Resolve real cgroup2 mount, parent hierarchy, boot, namespaces and inode/dev
   identities. Reject root, threaded/shared/prepopulated groups, missing memory
   controller or unverified delegation. No assumption of sudo/root on hosted CI.
2. An outer supervisor retains directory/counter handles for one fresh exclusive
   subgroup; takes a creation memory.events baseline of oom=oom_kill=0. Any
   nonzero creation counters fail freshness and cannot be subtracted away.
3. Before worker exec, place it in the group (verified atomic placement or held
   child handshake); close inherited privileged descriptors, drop UID/GID,
   supplementary groups, ALL capability sets and ability to regain privilege;
   set/verify NoNewPrivs, namespace identities and policy against setns/userns
   recovery. Supervisor stays outside. None of this is implemented by the model.
4. Deny worker writes to migration interfaces and relevant ancestors; protect
   supervisor control/evidence channels from same-UID ptrace, inherited FDs and
   filesystem substitution. Verify every alternate cgroup mount/namespace route.
   Kernel policy, not a PID scan, must enforce descendant/reparented containment.
5. Independently isolate all daemon discovery/IPC, retaining exact cold-compile
   semantics and download access. A private loopback/network+mount/IPC boundary
   and supervisor-mediated dependency egress is a design OPTION, not a proof.
   Fresh UID/HOME/GRADLE_USER_HOME/TMPDIR/XDG/java.io.tmpdir alone is insufficient.
6. Preserve process audits (PID/start ticks, pinned Java inode, ancestry, cgroup,
   namespaces), requiring an observed bound JVM but never treating that as the
   complete inventory guarantee. Supplementary missing identities remain gaps.
7. Await launcher exit, boundedly drain residual daemons with a proven mechanism
   (cgroup.kill only if supported and safe), observe populated=0, retain final
   memory.events read on the same handles/boot/identity, seal evidence BEFORE
   group removal. Preserve timeout/partial evidence. Missing drain/final-read
   proof is INCOMPLETE; positive events FAIL. Do not kill the outer supervisor.
8. Only an independently authenticated, reviewed evidence verifier could bind

PRIMARY KERNEL REFERENCES (read-only design references, not hosted evidence)
https://docs.kernel.org/admin-guide/cgroup-v2.html
Cgroup membership is inherited at fork. Migration requires relevant write
permissions. cgroup.kill affects a subtree; populated reflects live descendants.
These semantics motivate the design; they do not establish runner availability.
https://docs.kernel.org/userspace-api/no_new_privs.html
NoNewPrivs constrains privilege gain at exec; it is not a substitute for dropping
existing privileges/capabilities or preventing IPC and migration.
